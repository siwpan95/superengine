## 1. 八契约总表

| # | 契约名（注册表键） | Protocol | 版本 | 提供方 | 消费方 | 载体 | 干线 |
|---:|---|---|---|---|---|---|---|
| 1 | `worldspec_source` | `WorldSpecSource` | `1.0.0` | worldbuilder | 本仓装配层 + 外部集成者 | **文件**（worldspec 目录） | 玩法 |
| 2 | `terrain_source` | `TerrainSource` | `1.0.0` | worldbuilder | 3dworld（经本仓桥接） | **活对象**（`f(x,z)->h` 采样器） | 地形 |
| 3 | `mapgraph_source` | `MapGraphSource` | `1.0.0` | an-engine | 玩法侧 | **文件→对象**（`graph.json` → `MapGraph`） | 玩法 |
| 4 | `gameplay_world` | `GameplayWorld` | `1.0.0` | an-engine | 本仓（**托管**其 `Context`） | **活对象**（`Context`） | 玩法 |
| 5 | `terrain_sink` | `TerrainSink` | `1.0.0` | 3dworld | 本仓 + 表现层 | **活对象**（网格 `dict`） | 地形 |
| 6 | `render_sink` | `RenderSink` | `1.0.0` | 3dworld | 表现层（备用路径） | **活对象**（网格 `dict`） | 地形 |
| 7 | `dungeon_source` | `DungeonSource` | `1.0.0` | worldbuilder | *（暂无仓内消费方，见主设计 §6.1）* | **活对象**（`dict`，与 `graph.json` 同形） | 玩法（潜在） |
| 8 | `rules_kernel` | `RulesKernel` | `1.0.0` | an-engine | 玩法侧 | **数值**（骰子） | 规则 |

> 三条干线（主设计 §1.3）：**地形**（活对象、同进程、不落盘）／**玩法**（文件、跨进程、可复现）／**规则**（无状态纯函数）。
> `mapgraph_source` 是唯一「文件 → 对象」的过渡点；`dungeon_source` 的产物与之同形，故可无痛接入。

## 2. 方法清单（照抄 `contracts/protocols.py`）

> **全部 Protocol 只含方法、不含属性**。`@runtime_checkable` 带非方法成员时 `issubclass()` 会抛错；
> 这条由 `tests/test_baseline.py::test_protocols_are_runtime_checkable_and_methods_only` 守着。

| 契约 | 方法签名 |
|---|---|
| `worldspec_source` | `generate(width, height, seed, **kw) -> dict` · `save(world, out_dir, *, tile_m, generator) -> dict` · `load(spec_dir, *, layers=None) -> dict` · `validate_spec(spec_dir) -> List[str]` · `meta(spec_dir) -> dict` |
| `terrain_source` | `heightfield(source)` · `make_height_sampler(hm, tile_m=1.0, height_scale=1.0) -> Callable[[float,float],float]` |
| `mapgraph_source` | `mapgraph_from_worldspec(spec_dir, *, strict=False) -> Any` · `route(graph, start, goal, **kw) -> List[str]` · `nearest(graph, x, z, **kw) -> Any` |
| `gameplay_world` | `new_context() -> Any` · `provide_mapgraph(ctx, graph, key="mapgraph") -> Any` |
| `terrain_sink` | `clipmap_config(levels=5, grid=32, base_cell=1.0) -> Any` · `terrain_mesh(height_fn, camera=(0.0,0.0), config=None, world_size=None) -> Dict[str,Any]` |
| `render_sink` | `terrain_from_heightfield(hm, tile_m=1.0, camera=(0.0,0.0), config=None, height_scale=1.0) -> Dict[str,Any]` |
| `dungeon_source` | `generate_dungeon(width, height, rooms, seed) -> dict` · `dungeon_graph(grid, *, locks, loops, seed) -> dict` · `grammar_names(grammar, n, *, seed) -> list` |
| `rules_kernel` | `roll_dice(count, size) -> int` · `roll_d20() -> int` · `roll_3d6()` · `success_chance(skill_level) -> int` |

> **加方法 = 破坏性变更**：任何既有提供方都会立刻 `isinstance` 失败，装配期直接拒。
> 这不是「加个可选方法」那么轻，判据见 [`../release/版本策略.md`](../release/版本策略.md) §3.2，
> 流程动作见 [新增契约流程.md](新增契约流程.md) §2。

## 3. 提供方声明矩阵（`SUPPORTED_CONTRACTS`）

三仓在各自 `bridge.py` 声明，区间**统一为 `>=1.0,<2.0`**，8 个契约无遗漏、无重叠声明。

| 契约 | worldbuilder | an-engine | 3dworld |
|---|:---:|:---:|:---:|
| `worldspec_source` | ✓ | | |
| `terrain_source` | ✓ | | |
| `dungeon_source` | ✓ | | |
| `mapgraph_source` | | ✓ | |
| `gameplay_world` | | ✓ | |
| `rules_kernel` | | ✓ | |
| `terrain_sink` | | | ✓ |
| `render_sink` | | | ✓ |

> `check_provider()` 的方向性（主设计 §4.3）：**只校验 `supported` 自己声明的契约**，
> 不会反过来要求某个提供方满足全部 8 条。所以「一个仓只声明自己提供的 2~3 条」是正确用法，不是缺漏。
> `check_all(CONTRACT_VERSIONS, supported)` 会拒绝「注册表里有、但本仓没声明」以外的方向性误用——
> 具体是：本仓声明的每个契约名都必须在注册表里，且注册表版本要落在该区间内。

## 4. 契约 → 桥接 → 服务装配

| 提供方 | 桥接模块（唯一 import 三仓处） | cordis Service 名 | `inject` | 覆盖契约 |
|---|---|---|---|---|
| worldbuilder | `superengine/bridges/worldbuilder_bridge.py` | `worldbuilder` | `[]` | 1 / 2 / 7 |
| 3dworld | `superengine/bridges/tdworld_bridge.py` | `tdworld` | `['worldbuilder']` | 5 / 6 |
| an-engine | `superengine/bridges/anengine_bridge.py` | `anengine` | `['worldbuilder']` | 3 / 4 / 8 |

- 挂载顺序**不由 `configs/cordis.super.yml` 的书写顺序决定**，由 `inject` 依赖图决定 ⇒ worldbuilder 必先生效。
- entry `name` 受白名单 `ALLOWED_ENTRY_PREFIXES = ("superengine.bridges.",)` 约束（[ADR-002](../architecture/ADR-002-桥接层独占跨仓导入.md)）。
- 跨仓 import 只允许出现在 `bridges/`；由 `tests/test_no_cross_import.py` 守着。

## 5. 「改一处会牵动什么」影响矩阵

| 你想做的事 | 必须同步改的地方 |
|---|---|
| 加 / 删 / 改**方法签名** | `protocols.py` → 注册表的 `CONTRACT_VERSIONS` **major bump** → 三仓 `bridge.py` 的区间 → `test_baseline.py::EXPECTED_CONTRACTS` → 本页 §2 → 主设计 §1.2 → `CHANGELOG.md` |
| 新增一个**契约** | `protocols.py`（Protocol + `CONTRACTS`）→ `CONTRACT_VERSIONS` 加 `1.0.0` → 相关仓 `SUPPORTED_CONTRACTS` → `bridges/` → `cordis.super.yml` → 测试 → 本页 §1/§2/§3 → 主设计 §1 → 发布说明 |
| 只改**本仓装配层**（不动接缝） | 不动契约号 —— 组合仓自身版本（`pyproject.toml` `version`）与契约号是**两套独立计数器**，见 [`../release/版本策略.md`](../release/版本策略.md) |
| 兄弟仓自己发版 | **不动契约号**。只有当接缝形状变了才动；见主设计 §5 独立性论证 |
| 换 `worldspec v1` 文件格式 | 走**文件契约**的版本，不是 `CONTRACT_VERSIONS`；见主设计 §2.4「契约版本 ≠ 文件格式版本」 |

|---|---|---|

| 修注释 / 文档 / 测试，不动形状 | 不动 | patch |
| 只改装配层实现 | 不动 | patch / minor |

## 7. 诚实边界

- 本页的「版本」「方法」「区间」是**快照**，权威在代码；`test_baseline.py` 只机械断言快照未漂移，
  **不能**证明语义仍然正确。快照失效条款见 [`../quality/回归基线.md`](../quality/回归基线.md)。
- 「同形」是**约定**不是类型保证：`dungeon_graph` 与 `graph.json` 字段一致靠人工维护，
  没有机械门禁；见 [`../architecture/已知风险与缓解.md`](../architecture/已知风险与缓解.md)。
- `dungeon_source` 目前**没有仓内生产消费方**：契约形状、版本登记、桥接与
  `test_pipeline.py` 的形状断言都已就位，但**尚未被下游玩法代码消费**。
  主设计 [§6.4](契约体系设计.md) 明确把它归为「**已铺好但尚未接上的管线，不是缺口**」——
  §6.2 的四个真缺口是实体接缝 / 世界身份 / 时步语义 / 跨仓事件，不含地牢源。
