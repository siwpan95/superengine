# 悬空引用处置记录

> 记录一次「代码注释指向不存在的文档」的清理。判定日期：2026-11-04。
> 处置对象：3 处 `规划文档 §2.x` 引用。这类引用**不会让测试变红、不会让 import 报错**，
> 所以能长期潜伏；但对新人而言，它是一条点不开的死链，会把排障方向带偏。

## 1. 问题

早期开发时，代码注释以「规划文档 §2.6 / §2.7」指代设计决策。但本仓**从未存在**名为
「规划文档」的文件，`docs/` 下也没有编号为 §2.6 / §2.7 的锚点。三处引用均无法定位：

| 文件:行 | 原文 | 实际想说的（从上下文读出） |
|---|---|---|
| `superengine/assembly.py:4` | `三道门禁（对应规划文档 §2.7）` | 装配期的白名单 / 预导入 / 终态 ACTIVE 三道门禁；**三道各治一个已记录的 cordis 坑**（`name` 被直接 import 等同执行代码 / Loader 吞构造期异常 / PENDING 静默） |
| `superengine/bridges/anengine_bridge.py:4` | `**托管而非替换**（规划文档 §2.6-A）` | 不把 cordis 塞进 an-engine 替换其 `Context`；理由紧随其后写在注释里：`Context` 自述「源自 Cordis 三个算子」且**刻意零第三方依赖**，故外层 cordis 只管生命周期与回滚，内层保持零依赖、既有测试基线不受影响 |
| `superengine/bridges/tdworld_bridge.py:66` | `（两条路径并存，见规划文档 §2.6-B）` | **同进程不落盘的活对象路径**（`heightfield` → `make_height_sampler` → `terrain_mesh`）vs **worldspec 文件契约路径**（存档 / 跨进程时落盘）；紧邻上一句「全程同进程、不落盘」已把判据说清 |

三处**都在讲设计决策的理由**，且注释自身已把理由写全了 —— 悬空引用只是
「想去别处找更长的论证」，不是「这里没写理由」。这正是可以**安全内联 / 换指**
而不需要补造一份规划文档的原因：把推理补进注释或改指仓内真实文档即可，
读者不会丢信息。

**核查结论（实测）**：本仓**从未存在**名为「规划文档」的文件；
`git log -p --all` 全历史里 `规划文档` 只出现 3 次，正是这三行注释本身。
`/repos/` 下四个相关仓的 `*.md` 也搜不到 `§2.6` / `§2.7` / 托管而非替换 的章节。
`README.md` 与 `docs/新人开发上手指南.md` **没有**「规划文档」表述
（README 只在「四条核心纪律」里写了同一批设计结论，且是内联的，不指向外部文档），
所以 README 无需为这次清理改动。

> 这类引用属于**文档债**：它描述的设计意图是对的，但指向已经失效。
> 与 [ADR-002](../architecture/ADR-002-桥接层独占跨仓导入.md) 记录的 `RepoNotFound`
> 误导是同一类病 —— **报错/提示把你引向错误方向**，只是这次发生在注释里而非异常里。

既不新建一份事后追认的规划文档（那会再造一个可漂移的真相源），

## 3. 由此定下的纪律（写进评审清单）

1. **注释里的文档引用必须是仓内真实存在的相对路径**（从仓根算起，如 `docs/...`），
   且文件里能找到对应的可读锚点。不写「见规划文档」「见设计稿」这类无路径指代。
2. **章节号不是不能用，但要「先钉文件、再给锚点」，且锚点要指向稳定文档**。
   旧引用的病根不是 `§2.7` 这个数字，而是「**规划文档**」这个**无路径、不存在**的指代
   —— 改完的 `tdworld_bridge.py` 里 `docs/design/契约体系设计.md §2` 是可接受的：
   文件真实存在、路径可点开、§2 是主设计的固定主轴。
   节标题文字（如「1.2 逐条职责边界」）比裸数字更抗重排，优先用它。
3. **设计决策落 ADR，不放代码注释里当权威**。注释只做「指路」，一句话说清去哪看；
   长篇论证进 `docs/architecture/ADR-*.md`。
4. **新增/移动文档时反向 grep 一次**：`grep -rn "规划文档\|§2\." .` 应为空，
   且所有 `docs/...md` 引用路径存在。full 全评审把这条列为静态检查项。

## 4. 复核方式

```bash
cd superengine
grep -rn "规划文档\|§2\." superengine/ docs/ || echo "OK: 无悬空引用"
```

> 每条新增的 `见 docs/...` 都要能点开、且打开后能找到所说的那一节。
