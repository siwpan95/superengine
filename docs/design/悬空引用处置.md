# 悬空引用处置记录

> 记录一次「代码注释指向不存在的文档」的清理。判定日期：2026-11-04。
> 处置对象：3 处 `规划文档 §2.x` 引用。这类引用**不会让测试变红、不会让 import 报错**，
> 所以能长期潜伏；但对新人而言，它是一条点不开的死链，会把排障方向带偏。

---

## 1. 问题

早期开发时，代码注释以「规划文档 §2.6 / §2.7」指代设计决策。但本仓**从未存在**名为
「规划文档」的文件，`docs/` 下也没有编号为 §2.6 / §2.7 的锚点。三处引用均无法定位：

| 文件:行 | 原文 | 实际想说的 |
|---|---|---|
| `superengine/assembly.py:4` | `三道门禁（对应规划文档 §2.7）` | 装配期的白名单 / 预导入 / 终态 ACTIVE 三道门禁 |
| `superengine/bridges/anengine_bridge.py:4` | `**托管而非替换**（规划文档 §2.6-A）` | 不替换 an-engine 的 `Context`，只在外层托管生命周期 |
| `superengine/bridges/tdworld_bridge.py:66` | `（两条路径并存，见规划文档 §2.6-B）` | 同进程活对象路径 vs worldspec 文件契约路径并存 |

> 这类引用属于**文档债**：它描述的设计意图是对的，但指向已经失效。
> 与 [ADR-002](../architecture/ADR-002-桥接层独占跨仓导入.md) 记录的 `RepoNotFound`
> 误导是同一类病 —— **报错/提示把你引向错误方向**，只是这次发生在注释里而非异常里。

三处均为**只改注释、不改逻辑**；改完跑 `python -m tests.run_tests` 与 `boot --report` 应全绿。

---

## 3. 由此定下的纪律（写进评审清单）

1. **注释里的文档引用必须是仓内真实存在的相对路径**（从仓根算起，如 `docs/...`），
   且文件里能找到对应的可读锚点。不写「见规划文档」「见设计稿」这类无路径指代。
2. **宁可只写文件名，不写章节号**。章节号会随文档重排漂移，文件名不会。
   确需定位到节时，用节标题文字（如「1.2 逐条职责边界」）而非裸数字。
3. **设计决策落 ADR，不放代码注释里当权威**。注释只做「指路」，一句话说清去哪看；
   长篇论证进 `docs/architecture/ADR-*.md`。
4. **新增/移动文档时反向 grep 一次**：`grep -rn "规划文档\|§2\." .` 应为空，
   且所有 `docs/...md` 引用路径存在。full 全评审把这条列为静态检查项。

---

## 4. 复核方式

```bash
cd superengine
grep -rn "规划文档\|§2\." superengine/ docs/ || echo "OK: 无悬空引用"
```

> 上面这条只查**已登记的旧引用形态**。真正的兜底是人工评审：
> 每条新增的 `见 docs/...` 都要能点开、且打开后能找到所说的那一节。
