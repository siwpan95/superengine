# ADR 索引 —— 基础层决策记录

> ADR（Architecture Decision Record）记录**为什么这样设计**，以及**否决了什么**。
> 代码会变，决策理由不该跟着丢。改架构前先读这里。

| 编号 | 决策 | 状态 | 影响面 |
|---|---|---|---|
| [ADR-001](ADR-001-契约独立版本化.md) | 契约版本独立于三仓发版 | 生效 | `contracts/`、三仓 `SUPPORTED_CONTRACTS`、装配期校验 |
| [ADR-002](ADR-002-桥接层独占跨仓导入.md) | 唯一 import 三仓的地方收在 `bridges/` | 生效 | 三仓互不引用门禁、entry 白名单、跨仓改动流程 |
| [ADR-003](ADR-003-文件契约与服务契约并存.md) | 文件契约与服务契约并存、不互相替代 | 生效 | worldspec v1、M3 热重载、M4 换实现 |

## 记录格式

每条 ADR 固定五节：**背景 / 决策 / 理由 / 备选方案与为何否决 / 后果**。
「后果」必须写**代价**，只写收益的 ADR 是宣传稿不是决策记录。

## 一条贯穿三条 ADR 的元纪律

本仓的四条核心纪律里有两条直接对应 ADR：

1. **独立仓**：三仓平等，天然阻断「某一仓吞并另两仓」的耦合倾向（ADR-002）
2. **契约独立版本化**：`CONTRACT_VERSIONS` 不跟随任何一仓发版（ADR-001）
3. **文件契约与服务契约并存**：不互相替代（ADR-003）
4. **唯一 import 三仓的地方是 `bridges/`**（ADR-002）

## 新增 ADR 的时机

当出现以下任一情况，补一条 ADR 而不是只改代码：

* 引入第三个协作轴（除文件契约 / 服务契约之外）
* 允许 `bridges/` 之外的地方 import 三仓
* 契约版本策略改变（如改为跟随某仓发版）
* 装配框架从 cordis 换成别的
* 新增第四个兄弟仓

新增前先跑一遍 `python -m tests.run_tests`，确认你理解现有门禁在守什么。
