# ADR-002 · 桥接层独占跨仓导入

> 状态：**生效** ｜ 生效日 2026-10-24 ｜ 复核 2026-11-04
> 载体：`superengine/bridges/`、`superengine/_locate.py` 的 `import_bridge()`、
> `superengine/assembly.py` 的 `ALLOWED_ENTRY_PREFIXES`、
> `tests/test_no_cross_import.py`。

## 背景

组合仓整合三个独立仓时，最省力也最致命的写法是「谁需要什么就直接 import 谁的模块」。
一旦开了这个口子：

* 三仓之间会**互相**出现 import，从「可独立发布」退化成「一损俱损」；
* 某个仓的内部模块被别处直接引用后，它再也不能自由重构内部；
* 组合仓会慢慢长成事实上的「大仓」，吞并掉三仓的独立性 ——
  这正是本项目立项时要阻断的倾向。

cordis 还有一个放大风险的特性：配置树里 entry 的 `name` **会被当作模块名 import**，
等同于执行代码。所以「谁能被 import」本身就是安全边界。

## 决策

1. **唯一允许 import 三仓的地方是 `superengine/bridges/`**，
   且只经各仓自己提供的 `bridge` 友好接口（`<pkg>.bridge`）：
   `worldbuilder.bridge` / `allin_engine.bridge` / `world3d.bridge`。
2. **路径解析收在 `_locate.py`**：`import_bridge(name)` 是唯一入口，
   把「依赖缺失」与「仓没找到」分开报（见下方理由）。
3. **entry `name` 白名单**：`ALLOWED_ENTRY_PREFIXES = ("superengine.bridges.",)`，
   配置树里出现其它前缀直接 `AssemblyError`，在 import 之前就拦住。
4. **三仓互不引用由门禁机械保证**：`tests/test_no_cross_import.py` 扫描源码，
   发现跨仓 import 即红。
5. **跨仓改动走单独 PR**：本仓不修改兄弟仓的文件；发现兄弟仓的问题只出建议。

## 理由

* **可独立发布是硬约束**：三仓各自的 LICENSE / 版本 / 测试基线不受整合影响。
  M2 把 an-engine 的 `Context` **托管**而非替换，就是为了保它的零第三方依赖。
* **稳定接口面**：`bridge` 友好接口是三仓自己维护的适配层，组合仓只依赖这一层；
  三仓内部重构只要不动 bridge，组合仓就不用改。
* **报错不误导**：`_locate.py` 的 `import_bridge()` 捕获 `ImportError` 后包成
  `RepoNotFound`，**保留原始异常**作为 `from exc`。
  这很重要 —— 3dworld `_cordis_locate.py` 曾把「依赖缺失」误报成「没找到包」，
  排障方向被带偏。本仓 2026-11-04 又实证了一次：缺 `pyglet` 时报错是
  `仓 '3dworld' 缺少 bridge 接口模块`，真实原因藏在 `原始错误：No module named 'pyglet'`。
  ⇒ **看报错必须看到 `原始错误` 那一段**。
* **安全**：entry name 会被 import，白名单把「配置能执行什么」限死在本仓 bridges 内。

## 备选方案与为何否决

| 备选 | 为何否决 |
|---|---|
| 允许各处直接 import 兄弟仓内部模块 | 见效快，但三仓立刻互相耦合；内部重构会连锁破坏；等于吞并 |
| 把三仓做成 git submodule / 合并进本仓 | 直接违背「独立仓、不吞并」的立项前提；三仓各自发版节奏也没了 |
| 只靠文档约定「别跨仓 import」 | 约定会被时间侵蚀；`test_no_cross_import.py` 才是机械保证 |
| 把三仓能力复制到本仓（重写一层） | 出现两份逻辑，漂移必然发生；且违背「本仓不含任何算法」 |
| 让 cordis Loader 自己 import 任意 entry | entry name 等同执行代码，配置树成了任意代码执行入口 |

## 后果（代价）

1. **新增能力必须写 bridge 适配**：哪怕三仓已经有现成函数，也要在
   `superengine/bridges/` 加一层转发 + 在 `contracts/` 定义契约形状。多一步，
   换来的是边界清晰。
2. **传递依赖会穿透到组合仓**：这是本 ADR 最实际的代价。
   `world3d.bridge` 会触发 `world3d/__init__.py` → `from world3d.engine import *`
   → `world3d/engine/mathkit.py` → `pyglet.math`，于是**组合仓必须声明 pyglet**。
   2026-11-04 补进了 `pyproject.toml`，详见 [已知风险与缓解 §1](已知风险与缓解.md)。
3. **兄弟仓的问题只能建议、不能就地修**：例如想根治 pyglet 耦合，得在 3dworld
   单独提 PR（让 `mathkit` 改用纯 Python 向量实现，或让 `world3d/__init__.py`
   停止星号转发）。跨仓改动周期长，组合仓只能先靠声明依赖兜住。
4. **目录名 ≠ 包名**：`3dworld`→`world3d`、`an-engine`→`allin_engine`。
   自动定位按目录名找，clone 时改名会直接 `RepoNotFound`。
   这条已写进 [新人上手指南](../新人开发上手指南.md) 的漂移核对清单。
5. **白名单是前缀匹配**：`superengine.bridges.` 前缀下的模块都在放行范围，
   所以往 `bridges/` 里放文件等于扩大可执行面；新增文件仍要过 code review。
