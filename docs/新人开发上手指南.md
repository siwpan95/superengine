# 新人开发上手指南（模板）

> **文档性质**：这是一份「上手指南模板」，以下已用 `superengine` 的真实状态填充（核对日期：2026-10-29）。
> 换项目时可整体套用，只需替换「核对清单」里的取值。
> **开工前务必先核对「漂移核对清单」**：本模板所有命令/路径均来自仓库实测，若仓库后续演进，以仓库当前实际为准。

---

## 0. 这个项目是什么

`superengine` 是一个**组合仓**：把三个独立仓（`worldbuilder` / `an-engine` / `3dworld`）通过 cordis 装配成一条流水线，**但不吞并它们**。本仓只做四件事：**契约、桥接、装配、门禁**，不含任何算法。

- 契约层（`contracts/`）零依赖、独立版本化，是「三仓互不引用却仍能协作」的底线。
- 唯一允许 `import` 三仓的地方是 `bridges/`，且只经各仓的 `bridge` 友好接口。
- 装配有三道门禁（白名单 / 预导入 / 终态 ACTIVE）+ 一道「三仓互不引用」扫描。

## 一、环境准备

| 项目 | 要求 | 备注 |
|---|---|---|
| Python | **≥ 3.11** | 本机实测 3.13.14，满足要求 |
| 核心依赖 | `PyYAML`、`watchdog`、`numpy` | 见 `requirements.txt` |
| cordis | **无官方 pip 发行** | 见下方说明 |
| 三仓源码 | `worldbuilder` / `an-engine` / `3dworld` | 必须随本仓一起就位 |

**cordis 怎么来？**（重要，不是 `pip install`）
cordis 没有上 PyPI。它随 `3dworld` 一起 vendored 在 `3dworld/vendor/cordis/src`。
定位优先级（由 `_locate.py` 实现）：

1. `import cordis` 已能导入（你 pip 装过或已加入 path）；
2. 环境变量 `CORDIS_SRC` 指向 cordis 源码目录；
3. 与本仓**并排**的 `3dworld/vendor/cordis/src`（自动定位）。

> ✅ 最简做法：把四个仓并排放置（见第二节），`CORDIS_SRC` 可**不设置**，自动定位即可。

**建议建虚拟环境：**

```bash
cd superengine
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

> ⚠️ 若 `cordis` 导入失败，几乎总是它自身依赖缺失（PyYAML / watchdog）——先 `pip install -r requirements.txt`，别误判成「没找到包」。

## 二、代码获取

`superengine` 不是单仓，是**四仓协同**。少一个都跑不起来。

### 2.1 远端地址（两个远程，用户名不同，别踩）

| 仓 | gitee（origin，主） | github（mirror） |
|---|---|---|
| superengine | `https://gitee.com/siwpan/superengine.git` | `git@github.com:siwpan95/superengine.git` |
| worldbuilder | `https://gitee.com/siwpan/worldbuilder.git` | `git@github.com:siwpan95/worldbuilder.git` |
| an-engine | `https://gitee.com/siwpan/an-engine.git` | `git@github.com:siwpan95/an-engine.git` |
| 3dworld | `https://gitee.com/siwpan/3dworld.git` | `git@github.com:siwpan95/3dworld.git` |

> ⚠️ **用户名不一致是真实坑**：gitee 上叫 `siwpan`，github 上叫 `siwpan95`。clone / push 前确认当前 remote 指向哪个，别用错身份。默认以 gitee `origin` 为准。

### 2.2 克隆（四仓必须同级并排）

```bash
# 挑一个父目录，四个仓都 clone 到这一级：
mkdir -p ~/repos && cd ~/repos
git clone https://gitee.com/siwpan/superengine.git
git clone https://gitee.com/siwpan/worldbuilder.git
git clone https://gitee.com/siwpan/an-engine.git
git clone https://gitee.com/siwpan/3dworld.git
```

克隆后的目录结构（**目录名是定位依据，不要改名**）：

```
~/repos/
├── superengine/      # 本仓
├── worldbuilder/     # 包名也是 worldbuilder
├── an-engine/        # ⚠️ 目录叫 an-engine，但内部包叫 allin_engine
└── 3dworld/          # ⚠️ 目录叫 3dworld，但内部包叫 world3d
```

> 🔴 **最易踩的漂移点 —— 目录名 ≠ 包名**：
> - 目录 / 远端叫 `3dworld`，`import` 的包是 `world3d`；
> - 目录 / 远端叫 `an-engine`，`import` 的包是 `allin_engine`。
>
> 自动定位逻辑是「按目录名 `3dworld` / `an-engine` 找内部包 `world3d` / `allin_engine`」，
> 所以**目录名必须保持 `3dworld`、`an-engine` 原样**。若你 clone 时改了目录名，定位会直接 `RepoNotFound`。

### 2.3 若无法并排：用环境变量指路

```bash
export CORDIS_SRC=/abs/path/to/3dworld/vendor/cordis/src
export WORLDBUILDER_SRC=/abs/path/to/worldbuilder
export TDWORLD_SRC=/abs/path/to/3dworld
export ANENGINE_SRC=/abs/path/to/an-engine
```

## 三、启动 / 跑起来

所有命令**从本仓根目录 `superengine/` 执行**（以保证 `superengine` 包与 `configs/` 可定位）。

### 3.1 无头自检（不依赖 cordis / 三仓）

适合 CI、或你还没把三仓摆好时先验证「契约层」本身：

```bash
python selfcheck.py
# 成功：selfcheck ok: superengine contract layer (... checks: versions/registry/provider-gate)
# 失败：FAIL: <异常类型>: <原因>
```

> 这个入口**不导入 cordis、不导入三仓**，只实跑契约层的语义版本解析、兼容区间算术、提供方门禁。
> 在「已装 watchdog 的 cordis 环境」里，`boot` 可能因 Hmr 导入失败而跑不起来——此时用 `selfcheck.py` 兜底验证核心逻辑。

### 3.2 装配验证（headless）

```bash
python -m superengine.cli.boot            # 装配三仓 + 三道门禁
python -m superengine.cli.boot --report   # 额外打印契约版本与兼容区间
# 成功末行：SUPERENGINE_BOOT_OK
# 失败末行：SUPERENGINE_BOOT_FAILED
```

成功输出形如：
```
ok: WorldbuilderBridge ACTIVE inject=[]
ok: TdworldBridge      ACTIVE inject=['worldbuilder']
ok: AnengineBridge     ACTIVE inject=['worldbuilder']
```
> 挂载顺序**不由 yml 书写顺序决定**，而由各 Service 的 `inject` 依赖图决定（tdworld / anengine 都 inject worldbuilder，故 worldbuilder 必先生效）。

### 3.3 日常开发循环（常驻）

把 M3（cordis Hmr 热重载）和 M4（多实现可替换）接到日常：改配置或改三仓源码，地形就地重建，不用重启进程。

```bash
python -m superengine.cli.dev                # 常驻：监听配置 + 三仓 bridge 源码，自动重建
python -m superengine.cli.dev --once         # 只构建一次并打印报告
python -m superengine.cli.dev --set backend flat   # 改配置（下一轮生效，走 M4 换实现）
python -m superengine.cli.dev --status             # 看当前配置与默认值的差异
```

配置在 `configs/dev.json`，可用键与默认值：

| 键 | 默认值 | 说明 |
|---|---|---|
| `seed` | `7` | 随机种子（同参数结果一致） |
| `tile_m` | `2.0` | 单格边长（米） |
| `backend` | `clipmap` | 地形后端：`clipmap` 或 `flat`（M4 可热替换） |
| `levels` | `4` | clipmap 层级数 |
| `grid` | `16` | 网格分辨率 |
| `base_cell` | `2.0` | 基础单元尺寸 |

### 3.4 测试（三道门禁 + 流水线）

```bash
python -m tests.run_tests          # 聚合跑以下五个模块
# 分解：
python -m tests.test_assembly          # 装配门禁
python -m tests.test_pipeline          # 三仓流水线（M1/M2）
python -m tests.test_no_cross_import   # 三仓互不引用门禁
python -m tests.test_live              # M3 Hmr 热重载
python -m tests.test_backends          # M4 Impl 多实现可替换
```

## 四、常见问题 / 排障

**Q1：`ImportError: 未找到 cordis` 或 `cordis 源码已定位到 ... 但导入失败`**
- 先看是不是 cordis 自身依赖缺失：`pip install -r requirements.txt`（PyYAML / watchdog）。
- 再看 `CORDIS_SRC` 是否指向正确的 `.../cordis/src`；或确认 `3dworld/vendor/cordis/src` 存在且与本仓并排。

**Q2：`RepoNotFound: 找不到仓 '3dworld'` / `'an-engine'`**
- 多半是目录名被改了。目录必须叫 `3dworld`、`an-engine`（内部包才是 `world3d` / `allin_engine`）。
- 或没并排放置：本仓要能找到 `<superengine>/../3dworld` 与 `<superengine>/../an-engine`。
- 或用 `TDWORLD_SRC` / `ANENGINE_SRC` 等环境变量显式指路。

**Q3：装配失败，`SUPERENGINE_BOOT_FAILED`，fiber 停在 `PENDING`**
- `PENDING` = 依赖未就绪，**最常见是 `inject` 里的服务名与提供方挂载名不一致**（cordis 不报错、只一直等，进程可能静默退出——这正是门禁③要治的）。
- 单独 `import` 出问题的 entry 模块（如 `python -c "import superengine.bridges.tdworld_bridge"`）看真实异常；因为 Loader 会**吞掉插件构造期异常**。

**Q4：装配失败，fiber 是 `FAILED`**
- 构造 / 校验抛错（cordis 不会自动重试）。看报错里的契约/版本不兼容信息，检查三仓的 `SUPPORTED_CONTRACTS` 是否覆盖 `contracts.CONTRACT_VERSIONS`。

**Q5：`boot` 跑不起来但 `selfcheck.py` 能过**
- 正常现象。`boot` 需要 cordis + watchdog + 三仓全部可导入；在某些环境 cordis 的 Hmr 导入会因 watchdog 失败。先用 `selfcheck.py` 验证契约层，再排查 cordis/三仓环境。

**Q6：改了某个仓的源码，地形没变 / 没热重载**
- 开发循环只保证「**bridge 接口 + 本仓 entry**」两层被真正换掉。改了更深的**内部**模块，Python `importlib` 不会重绑定其他模块已持有的引用——**重启 `dev` 会话**即可。
- 监听用轮询（默认 0.5s）而非后台线程，改完稍等一轮即可。

**Q7：clone / push 提示权限或用户名不对**
- 见 2.1：gitee 是 `siwpan`、github 是 `siwpan95`。检查 `git remote -v` 与你的 SSH/凭证身份是否匹配。

**Q8：换 `backend` 没生效**
- `backend` 只认 `clipmap` / `flat`。用 `--set backend flat` 写入 `configs/dev.json`，下一轮生效；未知值会被 `dev` 直接拒绝。
