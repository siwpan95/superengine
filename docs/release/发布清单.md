>
> | 远端 | 地址 | 角色 |
> |---|---|---|
> | `origin` | `https://gitee.com/siwpan/superengine.git` | **主**（发版以此为准） |
> | `github` | `git@github.com:siwpan95/superengine.git` | **直推目标**（2026-11-05 起 SSH 直推；Gitee 镜像已被证伪） |

> ⚠️ **2026-11-05 实测证伪**：Gitee 镜像 7 天未同步；本机 SSH 直连 GitHub
> **可用**（`git push github master` 成功）。⇒ 现行做法：直推 + `ls-remote` 当场复核，
> 不再等待镜像；「GitHub 侧没看到」必须先查 `pushed_at` 判因，不能一律当延迟。

- [ ] **推前：核对两端远端，确认无分叉**
      ```bash
      git fetch --all
      git ls-remote origin
      git ls-remote github
      ```
      > **2026-10-29 实测踩过 `fetch first`**：远端可能已被他人 / 他机推进，
      > 闷头一推就被拒。**先 fetch + ls-remote 看两端是否领先本地。**
- [ ] **推前：本地工作区干净**
      ```bash
      git status --short      # 必须为空
      ```
- [ ] **推后：同样用 `ls-remote` 复核 IN_SYNC**
      ```bash
      git rev-parse HEAD
      git ls-remote origin refs/heads/master
      ```
      两串必须**逐字符相等**。
      > **不轻信 `git push` 打印的输出** —— 那是「推送动作」的回执，
      > 不是「远端确实同步」的证据。同步状态**只信 `git ls-remote`**。
- [ ] **推后：tag 在**两端**远端都可见**
      ```bash
      git ls-remote --tags origin
      git ls-remote --tags github
      ```
      > **2026-11-05 起改为直推**：`git push github v0.1.0` 后当场
      > `git ls-remote github refs/tags/v0.1.0` 复核（实测 `daaaf56` 已在两端）。
      > 旧「Gitee 镜像最短 5 分钟 / 等镜像跑完」结论已证伪，仅作排障知识保留。
      >
      > ⚠️ **两个 hash 不是矛盾，别「统一成同一个」**（实测 `git cat-file -t v0.1.0` = `tag`，
      > 是 annotated tag）：
      > - **`daaaf56`** = **tag 对象 hash**（`git rev-parse v0.1.0`，也是 `ls-remote --tags` 显示的值）；
      > - **`51400e9`** = `v0.1.0^{}` 解引用后的**目标 commit**（`git rev-list -n1 v0.1.0`，
      >   `git log --decorate` 显示 `51400e9 (tag: v0.1.0)`）。
      >
      > 所以本清单里「tag → `51400e9`」（讲**内容/门禁**）与「tag 均 `daaaf56`」
      > （讲**远端 ref 同步**）各指一层，都对。#11 汇编时**不要把两者改成同一个 hash**。
- [ ] **确认远端确实没有分叉**（不是只看本地）
      > `ls-remote` 只给 ref 指向的 sha，**不给分叉历史**。
      > 若两端 sha 不等，先 `git fetch` 后对比 `git log --oneline --left-right origin/master...master`，
      > 确认是「本地领先」而非「两边各有提交」。

### 6. 中文路径 git 过滤必须带 `-c core.quotepath=false`

> **已犯三次的坑**（工作区铁律 3）：git 默认把非 ASCII 文件名转义成
> `"\347\233\256\345\275\225…"`，于是**按名字过滤恒假**，
> 会误判「这个文件不在仓库里」——2026-09-28 那次差点因此放弃恢复一个本来能恢复的文件。

- [ ] **核对发布物清单时，所有按中文名过滤的 git 命令都带了这个参数**
      ```bash
      git -c core.quotepath=false ls-tree -r --name-only HEAD
      git -c core.quotepath=false status --short
      git -c core.quotepath=false diff --name-only --diff-filter=D
      ```
      > 本仓的 `docs/新人开发上手指南.md` 正是中文文件名，
      > 每次核对「发布物里有没有该文件」都会撞上这条。

### 7. 编码卫生

- [ ] **所有 `.md` / `.txt` 为 UTF-8 无 BOM**
      ```bash
      head -c 3 CHANGELOG.md | od -An -tx1     # 不得出现 239 187 191
      head -c 3 NOTICE     | od -An -tx1
      head -c 3 docs/release/版本策略.md | od -An -tx1
      ```
      > 中文 Windows 下 Python 文本 I/O 默认 GBK，**往返改写会烤坏中文**。
      > 编辑工具可能**静默剥掉 BOM**——所以要**复核首三字节**，而不是相信编辑器。
- [ ] **提交信息里的路径不带反斜杠**
      > 提交信息**落文件再 `-F`**（`git commit -F /tmp/msg.txt`）：
      > 既避开编辑器弹窗，也避开 Windows 路径被 bash 吃掉反斜杠。

## P1 · 发版核心动作（顺序执行，幂等可重入）

> 每个子命令重复跑安全（已存在就 SKIP）。中断后直接重跑。

- [ ] **0. 验令牌**（最便宜的失败前置）
      > 本机无文件式凭据（`~/.git-credentials` 不存在，凭据在 GCM 里），
      > 所以脚本取令牌**必须显式给**：`--token "<HEX>"` 或 `export GITEE_TOKEN=<HEX>`。
      > **`git push` 能推 ≠ 脚本能取到令牌**，二者是两条独立链路。
- [ ] **1. 打 tag**（语义化版本，本仓首次发布即 `v0.1.0`）
      ```bash
      git tag -a v0.1.0 -m "v0.1.0"
      git push origin v0.1.0
      ```
      > **tag 必须在 release 之前**——平台不允许跳过 Tag 直接建 release。
      > **前置状态：已解除。** `0.1.0` 的前提是「本仓能独立跑起来」
      > （见 `docs/release/版本策略.md` §5）；`pyglet` 依赖声明已于 2026-11-04 补全，
      > `v0.1.0` 也已打出（`daaaf56` → `51400e9`）。
      > ⇒ 本格是**发版流程模板**，下次发新版本时仍要重新确认「依赖声明未漂移 +
      > P0 全绿 + 主理人放行」，但**不再有「依赖没补全 ⇒ 不打 tag」这一条阻断**。
- [ ] **2. 建 release**（发行说明从 `CHANGELOG.md` 的 `0.1.0` 条目取）
- [ ] **3.（如需）传附件** —— 本仓是纯 Python 源码仓，**通常无二进制附件**；
      若要传，单附件 ≤100MB、每仓总附件 ≤1GB，附件名**不带路径分隔符**（会丢目录结构）。
- [ ] **4.（如需）转公开** —— 本仓已是公开仓（铁律 0），一般无需此步。
      > 若需转：`PATCH /repos/{owner}/{repo}` 的 body **必须带 `name`**，否则 400。

## P2 · 收尾与验收

> 别停在「上传成功」。

- [ ] **三层硬证据**（前两层足够下结论）
  - [ ] ① 远端 ref 与本地 HEAD **逐字符相等**
        ```bash
        git rev-parse HEAD
        git ls-remote origin refs/heads/master
        ```
  - [ ] ② 关键文件**字节级**在远端
        ```bash
        git rev-parse HEAD:NOTICE
        git cat-file -s <上面那个 sha>     # ⚠ 用 blob 口径，别用文件大小
        ```
        再用匿名 contents API 比对 `.sha` 与 `.size`。
        > **先比 blob sha，sha 相同就是同一份内容**——有 `.gitattributes` 时
        > 工作区 CRLF / 仓内 LF，文件大小每行差 1 字节。
  - [ ] ③ 工作区 `git status --short` 为空
- [ ] **发行说明含**：系统要求 → 安装步骤 → **许可与对应源码** → 本版本实测数据 → **已知限制（如实列）**
      > 本仓「已知限制」见 `CHANGELOG.md` 的 `0.1.0` 条目那一节——
      > **如实列出来**，别只报喜。
      > 源码指向要写 `git clone` 地址：平台自动附的源码包链接**不是直链**
      > （匿名拿到的是 HTML 页面）。
- [ ] **匿名视角复验**：不带令牌能打开仓库页 / raw / 发行版页
- [ ] **发行版指向的 commit 就是全量回归通过的那个**（不是「后来又改过」的那个）
- [ ] **`.git/config` 无凭据残留**
- [ ] **CHANGELOG 已更新**：本次发版的内容已写进 `CHANGELOG.md`，
      未发布内容在 `## [Unreleased]` 段
      > 本仓**首次发布**，所以现在 `## [Unreleased]` 是空的、`## [0.1.0]` 承载全部内容。
      > 打完 tag 后，后续变更一律进 `Unreleased`。
