# 回归基线 —— 「改动没破坏基线」的判定依据

> 时点：2026-11-04 ｜ 实测环境：Windows / Python 3.13.14 /
> `.venv` 内 PyYAML 6.0.3 · watchdog 6.0.0 · numpy 2.5.4 · pyglet 2.1.16。
> 机械断言见 [`../../tests/test_baseline.py`](../../tests/test_baseline.py)；
> 本文记录**人工可复核的输出形态**（那些不适合写成硬编码断言的部分）。

## 0. 口径说明（避免误读数字）

`python -m tests.run_tests` 打印的「N 项」是**输出里 `ok:` 的行数**，
而每个测试函数会打**两行** `ok:`（一行自定义描述 + 一行函数名）。
⇒ **`项` = 2 × 测试函数数**。别把「90 项」当成 90 个独立断言。

| 模块 | 输出项 | 实际测试函数数 | 覆盖 |
|---|---|---|---|
| `test_assembly` | 12 | 6 | 装配门禁（契约版本 / fiber 终态 / 依赖图） |
| `test_no_cross_import` | 6 | 3 | 三仓互不引用门禁 |
| `test_pipeline` | 16 | 8 | 三仓流水线（M1 表现腿 / M2 玩法托管） |
| `test_live` | 12 | 6 | M3 cordis Hmr 热重载 |
| `test_backends` | 14 | 7 | M4 reflect.Impl 多实现可替换 |
| `test_devloop` | 12 | 6 | 开发循环（M3+M4 接入日常） |
| `test_baseline` | 18 | 9 | 回归基线（契约快照 / 依赖声明 / 零依赖边界） |
| **合计** | **90** | **45** | **7 模块 / `ALL_TESTS_PASSED`** |

`python selfcheck.py` → `selfcheck ok: superengine contract layer (23 checks: versions/registry/provider-gate)`。

## 1. 装配 fiber 基线

`python -m superengine.cli.boot --report` 期望（**顺序由 `inject` 依赖图决定，
与 yml 书写顺序无关**）：

```
  ok: Loader ACTIVE inject=[]
  ok: isolate ACTIVE inject=[]
  ok: WorldbuilderBridge ACTIVE inject=[]
  ok: TdworldBridge      ACTIVE inject=['worldbuilder']
  ok: AnengineBridge     ACTIVE inject=['worldbuilder']
SUPERENGINE_BOOT_OK
```

**判据**：5 个 fiber **全部 ACTIVE**；末行必须出现 `SUPERENGINE_BOOT_OK`。
出现 `PENDING` = 依赖名拼错（cordis 不报错只一直等）；出现 `FAILED` = 构造/校验抛错。

## 2. 契约版本 → 兼容区间对照表

`CONTRACT_VERSIONS` 是唯一权威，当前 **8 个契约全部 1.0.0**：

| 提供方 | 契约 | 版本 | 声明区间 |
|---|---|---|---|
| worldbuilder | `worldspec_source` | 1.0.0 | `>=1.0,<2.0` |
| worldbuilder | `terrain_source` | 1.0.0 | `>=1.0,<2.0` |
| worldbuilder | `dungeon_source` | 1.0.0 | `>=1.0,<2.0` |
| tdworld | `terrain_sink` | 1.0.0 | `>=1.0,<2.0` |
| tdworld | `render_sink` | 1.0.0 | `>=1.0,<2.0` |
| anengine | `gameplay_world` | 1.0.0 | `>=1.0,<2.0` |
| anengine | `mapgraph_source` | 1.0.0 | `>=1.0,<2.0` |
| anengine | `rules_kernel` | 1.0.0 | `>=1.0,<2.0` |

前两项由 `test_baseline.py::test_contract_registry_snapshot` 机械断言；
区间由 `test_assembly.py::test_contract_versions_within_declared_intervals` 在装配期验。
**主版本不同即视为不兼容**（`>=1.0,<2.0` 是约定写法）。

## 3. 开发循环基线（M3 + M4）

`python -m superengine.cli.dev --once` 期望：

```
tkinter 不可用，Tkinter GUI 功能已禁用（BaseWindow/StatusPanel/Styles = None）
tkinter 不可用，Game UI 组件已禁用
[dev] backend=clipmap seed=7 verts=1024 h=0.235~0.721 registry=10
SUPERENGINE_DEV_OK
```

| 字段 | 基线 | 说明 |
|---|---|---|
| `backend` | `clipmap` | 默认；`--set backend flat` 可走 M4 换实现 |
| `seed` | `7` | 同参数结果一致 |
| `verts` | `1024` | 网格顶点数，随 `grid` / `levels` 变 |
| `h` | `0.235~0.721` | 高度范围，随 `seed` / `tile_m` 变 |
| **`registry`** | **`10`** | **热重载不泄漏的判据**——涨了就是「两份逻辑同时跑」 |

`registry=10` 是 M3 的核心判据（Loader / isolate / 3 个 Bridge /
TerrainBackendHost / TerrainConsumer / TimerService / Hmr 等编组后的规模）。
**这个数字不写进硬编码断言**（它会随合法的新插件增长），而是作为人工复核的
相对判据：**同一会话内热重载前后必须不增长**。

### 两条联动（改了什么会走哪条）

| 改什么 | 走哪条 | 表现 |
|---|---|---|
| `configs/dev.json` 的 `backend` | **M4** | 实现热替换，消费方代码不动 |
| 三仓 bridge 源码 | **M3** | 底层模块重导 + entry fiber 换新，registry 不增长 |
| `seed` / `tile_m` / 网格参数 | 重建 | 地形随之变化，同参数结果一致 |

## 4. 依赖基线

`pyproject.toml` 的 `dependencies`（**唯一事实来源**，`requirements.txt` 通过 `-e .` 转发）：

```
PyYAML>=6.0,<7     # vendored cordis 硬依赖
watchdog>=4.0,<7    # vendored cordis 硬依赖
numpy>=2.0          # worldbuilder 侧，bridge 顶层 import
pyglet==2.1.16      # 3dworld 侧，经 mathkit 传递；锁版本对齐 3dworld
```

由 `test_baseline.py` 机械断言：四个包**声明了且能 import**、`pyglet` 必须在列、
`requirements.txt` 只能是 `-e .` 转发、`contracts/` 层零第三方依赖。

## 5. 判定「改动没破坏基线」的流程

```bash
python scripts/bootstrap.py --check-only     # 四仓 / cordis / 依赖 就位
python selfcheck.py                          # 23 checks
python -m tests.run_tests                    # 7/7 模块，ALL_TESTS_PASSED
python -m superengine.cli.boot --report      # 5 fiber ACTIVE + SUPERENGINE_BOOT_OK
python -m superengine.cli.dev --once         # registry=10 + SUPERENGINE_DEV_OK
```

全绿才算基线未破。**任一失败都要先定位，不要以「环境问题」绕过**——
2026-11-04 的 pyglet 事故就是长期被当成环境问题绕过去，直到干净机 clone 才暴露。
（3dworld 在 2026-10-29 有同款记录：numpy 漏声明让 10 个测试模块长期红着被绕过。）

## 6. 本基线的失效条件

以下任一发生，本表**过期，需重新实测并回写**：

* 新增 / 删除契约，或任一契约升版本
* 新增 / 删除装配插件（影响 `registry` 基线）
* 更换 Python 大版本或 pyglet 版本
* 三仓任一仓的 `SUPPORTED_CONTRACTS` 变更
* CI 平台矩阵调整

快照型事实必须带失效条款——权威归随日期演进的事实流水，不归这份快照。
